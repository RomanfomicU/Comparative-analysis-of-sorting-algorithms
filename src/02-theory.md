# Теоретические оценки

## Нижняя граница для сортировок сравнениями

Работу любого алгоритма сортировки сравнениями можно представить в виде двоичного
дерева решений, листья которого соответствуют всем $n!$ возможным перестановкам
входа [@cormen2013]. Высота двоичного дерева с $n!$ листьями не меньше $\log_2 n!$,
поэтому в худшем случае требуется не менее

$$
C_{\min}(n) = \lceil \log_2 n! \rceil
$$

сравнений. По формуле Стирлинга $n! \approx \sqrt{2\pi n}\,(n/e)^n$, откуда

$$
\log_2 n! = n \log_2 n - n \log_2 e + O(\log n) \approx n \log_2 n - 1{,}443\,n.
$$

Таким образом, ни один алгоритм этого класса не может быть асимптотически быстрее
$\Theta(n \log n)$.

## Сортировка вставками

Алгоритм последовательно вставляет очередной элемент в уже упорядоченный префикс.
Число сравнений определяется числом *инверсий* — пар $(i, j)$ с $i < j$ и $a_i > a_j$.
Для случайной перестановки каждая из $\binom{n}{2}$ пар образует инверсию с
вероятностью $1/2$, поэтому в среднем

$$
C_{\text{ins}}(n) \approx \frac{n(n-1)}{4} + n \approx \frac{n^2}{4}.
$$

## Сортировка слиянием

Массив делится пополам, половины сортируются рекурсивно и затем сливаются за
линейное время. Трудоёмкость описывается рекуррентным соотношением

$$
T(n) = 2\,T\!\left(\frac{n}{2}\right) + \Theta(n),
$$

решение которого по основной теореме о рекуррентных соотношениях даёт
$T(n) = \Theta(n \log n)$. Число сравнений в худшем случае [@knuth1998]:

$$
C_{\text{merge}}(n) = n \lceil \log_2 n \rceil - 2^{\lceil \log_2 n \rceil} + 1.
$$

## Быстрая сортировка

Алгоритм, предложенный Ч. Хоаром [@hoare1962], выбирает опорный элемент и
разбивает массив на две части: меньше и больше опорного. При случайном выборе
опорного элемента математическое ожидание числа сравнений удовлетворяет соотношению

$$
C(n) = n - 1 + \frac{2}{n} \sum_{k=0}^{n-1} C(k),
$$

решение которого

$$
C_{\text{quick}}(n) = 2(n+1)H_n - 4n \approx 2 n \ln n \approx 1{,}386\, n \log_2 n,
$$

где $H_n = \sum_{k=1}^{n} 1/k$ — $n$-е гармоническое число. В худшем случае
быстрая сортировка требует $\Theta(n^2)$ сравнений, однако при случайном выборе
опорного элемента вероятность такого исхода пренебрежимо мала [@sedgewick2011].

## Пирамидальная сортировка

Пирамидальная сортировка [@williams1964] строит на массиве двоичную кучу за $O(n)$,
после чего $n - 1$ раз извлекает максимум с восстановлением свойства кучи за
$O(\log n)$. Каждый шаг просеивания требует до двух сравнений на уровень, поэтому

$$
C_{\text{heap}}(n) \le 2 n \log_2 n + O(n).
$$
